# R5 企业员工网页小助手

本功能把已有智能体放到企业门户、业务系统等网页中。宿主网页和 MindCreek 可以使用不同域名；员工使用企业账号登录，以自己的空间与知识权限提问。

## 1. 安装要求与启用

- 网关和前端都需要包含 R5 实现；旧 R4 镜像仅修改环境变量不能获得此功能。此次源码交付不自动更新先前导出的 AMD64 离线包。
- 沿用已有企业 OAuth2、本地 admin、默认空间和模型配置。生产环境的 MindCreek 与宿主网页均使用 HTTPS。
- 网关启动时应用新增产品迁移 `000016_employee_assistant`；升级前备份 PostgreSQL。历史迁移、业务表和卷保持原样。
- 前端 Nginx 需要更新为本版本模板，包含 `/assistant/` 的动态 CSP 校验及 `/mindcreek-assistant.js` 静态文件。外层代理不能再给该路径附加 `X-Frame-Options: SAMEORIGIN/DENY` 或冲突的 `frame-ancestors`。其他页面保持禁止跨来源嵌入。
- 企业配置增加 `MINDCREEK_EMPLOYEE_ASSISTANT_ENABLED=true` 后重建网关容器。默认值为 `false`，要求同时启用原生空间与企业身份模式。

请按原有[企业部署手册](R4_AMD64_ENTERPRISE_DEPLOYMENT_ZH.md)使用本次源码重新构建、验证和版本化镜像；镜像的企业服务器发布仍属于 R6。开发验证可运行 `make r5-ui-build`、`make r5-gateway-build`、`make r5-api-probe`。前端构建设置 `R5_NODE_BIN` 指向 Node 24。AMD64 构建入口为 `python3 tools/release/build_enterprise.py --profile r5`，使用 R5 的前端证据，不覆盖 R4 验收报告。离线包组装及目标环境验证需另外执行。合成验收使用独立临时项目及本机 18685–18688 端口，不接入企业身份或真实模型。

## 2. 发布到网页

1. 以目标空间的 **Owner 或 Admin** 登录主站，在“智能体”页面点击“发布到网页”。本地 admin 可以管理其具有相应角色的空间；平台管理员不自动获得其他空间内容权限。
2. 选择已配置知识范围的智能体，点击“新建发布渠道”。Contributor 和 Viewer 不能管理发布渠道。
3. 填写渠道名称、允许来源、欢迎语、调用限额和是否允许附件，保存后启用。允许来源示例：`https://portal.example.com`、`https://work.example.com:8443`。每行一个来源，不含路径、尾斜杠或通配符。仅回环域名允许 HTTP 用于开发。
4. 复制页面生成的代码，放进允许来源网页的 HTML。宿主页面 CSP 需要允许从 MindCreek 加载脚本（`script-src`）和框架（`frame-src`）。
5. 员工点击右下角“知识小助手”，再点击“企业登录”；企业认证在第一方弹窗中完成，验证后的员工身份返回小助手。首次员工开户仍自动加入默认空间 Viewer；访问其他空间需要先加入该空间。

代码形式如下，实际 ID 使用页面生成的值：

```html
<script src="https://mindcreek.com/mindcreek-assistant.js"
        data-space="空间ID" data-channel="渠道ID" defer></script>
```

代码中的标识不是授权凭证。不要把原生发布令牌、API Key、管理员密码或员工访问令牌写进网页。宿主页面不能接收到员工令牌。

## 3. 员工登录和会话

- 弹窗复用现有 OAuth2 回调、员工开户与恢复流程，不需要新增企业 OAuth 回调地址。允许浏览器弹窗；IdP、外层代理若使用 `Cross-Origin-Opener-Policy` 切断窗口关系，需要在 R6 调整适用策略并验证。
- 本地 admin 用于管理发布；消费小助手要求企业员工身份。本地管理员需要以企业身份重新认证后才能使用助手。
- iframe 的访问令牌只保存在内存。弹窗的第一方主站仍使用既有 R2 会话存储。iframe API 使用 bearer，不依赖第三方 Cookie。
- “退出助手”清除该 iframe 的内存会话并重新加载；它不会退出所有主站窗口或企业 SSO。主站执行退出后，原生令牌撤销使助手后续请求失效。令牌到期时重新打开企业登录弹窗。
- 只显示本人、当前渠道及来源的历史会话。主站和 MCP 不能通过普通会话路径读取渠道绑定的会话。当前渠道列表最多显示最近 100 个会话，每次历史加载最多 100 条消息。
- 管理员关闭/删除渠道、移除员工或撤销资源权限后，新请求和流式重连重新鉴权。已经开始的流不保证立即中止，已返回内容不追溯删除。
- 新建会话和每次提问计入限额；每分钟限额按员工计算，每日限额按渠道计算，日界线为 UTC。计数保存在数据库，重启网关不会清空。

## 4. 排障

| 现象 | 检查项 |
|---|---|
| 未显示“发布到网页” | 网关功能开关；前端是否为 R5；当前空间是否为 Owner/Admin |
| 框架无法显示 | 宿主 `frame-src`；MindCreek 外层代理 X-Frame-Options/CSP；来源协议、端口是否完全匹配 |
| 登录窗口被阻止或失去连接 | 浏览器弹窗权限；实际 IdP/代理的 COOP；从助手重新打开弹窗 |
| 登录后仍无法访问 | 员工是否完成开户且属于渠道空间；渠道是否启用；Agent 与知识是否仍可访问 |
| HTTP 429 | 每员工每分钟或渠道每日配额已满；等待窗口重置或由管理者调整 |
| 图片、引用失败 | 当前会话与知识权限；渠道来源；资源是否已经删除；检查对应请求 ID |
| 停用后无法恢复历史 | 恢复渠道及权限后重新登录；历史绑定不会自动改到其他渠道/来源/员工 |

不以放开匿名 `/embed/`、公开资源短链或共享管理员令牌解决故障。只收集状态码、稳定错误码及请求 ID；不记录提示词、企业文档或令牌。

## 5. 回退和 R6

紧急关闭使用 `MINDCREEK_EMPLOYEE_ASSISTANT_ENABLED=false` 并重建网关，或停用某一渠道。保留数据库中的绑定，关闭后仍阻止从主站绕过渠道访问。

非空 `assistant_sessions` 会阻止迁移 000016 的破坏性回退。不要为了降版删除绑定后运行旧网关，那会丢失渠道限制；使用同版本关闭功能，或恢复包含应用版本、数据库与文件的成套备份。R6 需验证真实企业 OAuth/CA/代理、浏览器策略、真实模型与图片、员工离职流程、备份恢复及负载。合成通过不替代这些检查。
