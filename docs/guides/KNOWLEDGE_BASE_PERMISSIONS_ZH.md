# 知识库可见性与协作权限

更新：2026-10-18。适用于本次增量的原生空间网关及配套前端，不适用于尚未升级的已有发布包。规则见[设计](../plans/KNOWLEDGE_BASE_ACL_DESIGN_ZH.md)，验证范围见[验收](../plans/KNOWLEDGE_BASE_ACL_ACCEPTANCE.md)。上游 WeKnora 保持未修改。

## 使用方式

新建知识库默认仅创建者与本空间 Owner/Admin 可见。在知识库的“访问与协作”中，可选择仅自己和管理者、指定成员或空间内公开。公开只向当前空间有效成员开放阅读和问答，不授予下载或写入，也不允许匿名、跨空间访问。

创建者和 Owner/Admin 可给其他编辑逐项授予：上传/新增文档、修改文档、删除文档、下载原文件、修改分块、删除分块、导出分块。下载授权同时允许原文件预览；删除文档会级联删除所属分块，重新解析需要文档修改、分块修改和分块删除三项权限。只给可见权限的成员可以阅读获准解析内容和用于问答，不能下载原文件。

协作者不能改知识库名称、配置、删除整个知识库或转授权。Viewer 只能获得可见和问答权限，即使曾经创建过该库也不能继续写入或管理授权。Owner/Admin 可以管理当前空间所有普通知识库；平台管理员身份本身不提供其他空间内容权限。

权限更改按版本保存；遇到冲突后刷新最新策略再修改，不覆盖他人的更改。页面重新聚焦、切换空间或身份变化会刷新权限，API 每次重新检查，隐藏按钮不是最终授权边界。

## 启用协作执行

Owner 在空间设置中单独启用“知识库协作写入”执行授权。它与成员管理授权分开，不能因为已经启用 Admin 成员管理就自动允许内容代理。网关把 Owner 会话加密保存在产品数据库，使用限定知识库的内部内容 Key 或经约束的服务端会话调用固定接口，记录实际操作者；内部凭据不会返回给协作者。

协作执行授权失效时拒绝依赖代理的操作；可用的普通阅读不因此升级权限。撤销先关闭产品入口，再清理内部 Key。失败时保留需要清理的元数据并报告错误，不能直接删库掩盖失败。受理前的权限变更与写入使用身份、空间、知识库的有序数据库锁；上游已受理的解析任务不声称能被撤回。

## API Keys

Admin 只管理自己的 Key；Owner 管理全部普通 Key。知识访问须同时满足原生能力、显式知识库范围和产品操作范围。`retrieve` 不等于下载，`ingest` 不等于七项内容操作全部开放，`full_access` 也不自动授予全部私有库。

Owner 可以明确选择“全部知识库，包括以后新建的私有库”，Admin 必须指定知识库。已有 Key 未建立产品映射时拒绝知识访问，Owner 可核对后保存明确范围或重建。用于内容写入的原生能力需要满足对应接口，读取知识库元数据和检索需要 `retrieve`；配置七项操作不能提升原生能力。机器 Key 本期不提供知识库生命周期、配置或 ACL 管理权限。

成员停用、移除、退出或降级后，旧 Key 及相应知识授权不能因重新加入、启用或提升角色自动恢复。创建者离开后知识库仍归空间管理，Owner/Admin 可显式恢复其创建者资格。

## 当前可用范围与限制

- 文档、FAQ、Wiki 基本内容读写、受限检索、引用、历史、图谱和分块导出经过产品权限检查。FAQ 批量导入进度须有可信的任务与知识库归属。
- 原文件下载和预览按文档 ID 核验父知识库。图片修复包使用可信解析记录自动恢复已登记历史图片；普通成员缺少归属证据的图片需安装运维人员独立核验后确认。操作见[图片权限修复与升级](IMAGE_PERMISSION_RECOVERY_ZH.md)。未知派生资源与通用任务仍拒绝，不会仅凭 URL 中的知识库 ID 放行。
- 跨空间共享、复制知识库、跨库移动、Wiki 自动修复/重建等未完成范围证明的可选入口关闭。
- Agent 使用已验证的只读工具。内部写工具、任意 SQL 分析、数据库查询、外部 MCP/Skills、Web 搜索、沙箱和记忆关闭；普通内容写入使用知识库页面/API。保存 Agent 时必须显式关闭记忆；Web 问答和 MCP ask 每次都检查空间记忆开关，已有空间开启记忆时拒绝问答，防止继承跨会话内容或原生回退至无 Agent 模式。内置或旧只读 Agent 的缺省记忆值仅在此空间检查通过后允许继承。旧 Agent 需重新保存兼容配置，旧会话有沙箱绑定时需新建会话。
- 问答请求强制返回受保护资源句柄，屏蔽存储路径和签名链接。以前已经返回或下载的内容不能通过撤销追回。

## 升级与恢复步骤

本功能已纳入 2026-10-19 AMD64 完整包，R4 图谱版和 1009 版见[专用升级指南](UPGRADE_R4_AND_20261009_ZH.md)；尚未执行企业服务器升级。升级时使用新的网关及配套前端，不与旧网关混跑，也不能让用户绕过网关直连原生 App/存储。

1. 先备份产品数据库、原生数据库和安装加密密钥；保持原生服务及对象存储私有。准备暂停员工流量的切换窗口。
2. 应用产品迁移 000018、000019（依赖已有 000017）。迁移不修改原生表。迁移可重复执行；down 遇到保留的 ACL、撤销代次、创建记录或执行/机器授权数据会拒绝，不能通过清表强行回退。
3. 只将新版本网关、配套前端及产品内置 Agent 配置接入验收环境。新的 `deploy/phase5/builtin_agents.yaml` 显式关闭记忆、外部 MCP/Skills 与沙箱，企业打包使用同一文件；已有数据库内置 Agent 覆盖记录也须核对。以 Owner 枚举每个空间历史知识库并读取权限策略，使可信原生创建者绑定按需落库，默认为受限；未知创建者仅管理者可见。核对数量、异常创建记录、共享关系和 Key 映射后，才开放员工流量。系统临时/历史索引库不能公开为普通库。
4. Owner 核对协作执行授权和机器访问范围；创建超时有幂等操作记录时，通过“创建恢复”确认原生实际结果并绑定，不盲目重试新建。创建者 ID 和目标空间必须与可信原生结果一致。创建前完整清单以外的待确认新库仅供管理员恢复，不能借历史库初始化或改为公开解除隔离。
5. 用 Owner、Admin、两个编辑和 Viewer 验证私有/指定/公开、七项操作、撤销、问答与 API Key。真实 OAuth、模型、存储预览与任务在目标环境分别验收；本地合成测试不替代这些检查。
6. 如需回退，保持 ACL 网关或关闭知识访问，再恢复一致的数据库及安装密钥。回到旧网关会恢复其宽松权限，不属于安全回退。

当前实现采用可信元数据首次访问时初始化历史策略，不会自动扫描或改写企业现存库，也没有替企业确认旧共享和机器范围。此盘点是上线前的执行步骤。
