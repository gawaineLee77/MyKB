## 修复范围

旧版页面重新获得焦点、重新可见或收到知识库权限变化时清空所有资源缓存，却只重新加载知识库，导致模型与智能体列表暂时或持续为空，界面误报“模型未配置”。新逻辑在同一身份内保留已经成功读取的模型列表，并重新核对模型、智能体和知识库。模型列表短暂请求失败时保留既有值，成功返回空列表时仍反映真实删除。

权限相关知识库缓存继续失效重查；撤权前的旧请求不能回写或返回已失效结果，旧请求的结束也不能清除后续请求的状态。账号、空间及角色变化继续清空全部资源并重载页面。未修改上游源码，未新增模型数据迁移。

合并包继续提供历史知识库／问答图片鉴权和 `bin/image-resources` 审核确认工具。已登记且有可信解析记录的历史图片可以自动恢复；缺少关联的已登记资源需人工核验，资源登记或图片本身缺失不能凭正文链接自动重建。详见[图片恢复说明](../guides/IMAGE_PERMISSION_RECOVERY_ZH.md)。

## 环境限制与封装

本机为 ARM 主机上的 AMD64 Docker 模拟，独立数据库预检再次复现既有 `paradedb.score` 查询导致 PostgreSQL `signal 6: Aborted` 的现象，临时容器已清理。实际问答烟测使用显式配置的合成向量检索库；随包默认索引设置未改变。物理 Linux AMD64 上的 BM25／混合检索、真实企业 OAuth／模型、容量及业务资料仍需目标环境验收。
