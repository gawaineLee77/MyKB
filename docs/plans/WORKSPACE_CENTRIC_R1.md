### 已验证的关键差异

1. 原生登录 DTO 返回 `token`，刷新接口返回 `access_token`；适配器不能混用。无空间身份可以调用 `/auth/me` 和允许的开户相关路径，`/system/info` 等业务接口会要求空间。
2. 关闭原生自建开关时，系统管理员没有独立豁免；开启时 Viewer 也能主动建空间。因此 R2 必须在产品入口实施平台管理员创建策略，并同步返回能力，不能只切换一个上游环境变量。
3. 原生角色管理可直接复用，不需要新角色体系。成员移除可能先撤销会话而返回 401；重新认证后再验证目标空间访问拒绝，不能只断言一种拒绝状态。
4. 原生渠道 token 不是企业员工会话。其 Origin 和渠道撤销机制有效，但不能代替成员撤销；需要 R5 的员工会话适配。
5. 目前没有发现上述必要流程必须修改上游源码。跨服务幂等、正式员工小助手与浏览器行为仍由后续产品实现及验收证明；出现公开接口无法满足的必要约束时，再走补丁提案流程。

### 产品侧合成回归

[网关验证记录](evidence/r1-gateway-tests.json)和[完整输出](evidence/r1-gateway-tests.txt)：**30 个带测试的网关包非缓存通过**，命令使用 `GOFLAGS='-mod=readonly -count=1' make phase1-gateway-test`。包括已有 broker/OAuth、安全、模型、授权和会话测试，以及本次两个 R1 边界特征测试。

两个新测试证明：现有业务 principal 解析拒绝无空间普通用户和系统管理员；现有企业身份门禁在无空间时不会绑定本地账户。已有测试同时证明企业模式关闭本地密码登录/刷新和部分邀请入口。它们记录 R2 的改造起点；后续修改行为时需同步更新特征测试，不能把旧拒绝行为保留为新开户规则。

非缓存测试最初因沙箱禁止 httptest 本地监听而无法运行；取得该范围执行权限后已重新通过。未将环境限制误记为业务失败或跳过通过。
